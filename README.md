# MiHome-Windows

米家设备的 Windows 桌面控制端。基于 [mijiaAPI](https://github.com/Do1e/mijia-api)
构建图形界面，扫码登录后即可在本地窗口中查看和控制家里的全部米家设备。

> **注意：当前项目仍处于早期版本。** 作者个人米家设备有限，无法对各类设备做针对性适配测试，因此 UI 和操作逻辑的完善度不算很高。不过基础使用（扫码登录、设备列表与常用控制、托盘、小爱语音等）已无大碍，但需适配更多设备功能则需要社区支持了。

## 功能

- **扫码登录**：米家 APP 扫二维码，登录凭据与上游依赖的 CLI 共用
- **设备列表**：按家庭、房间分组，实时显示在线状态；可在设置里隐藏「无控制功能」或「离线」的设备；设备名过长时自动折成两行并在末尾省略，完整名称见鼠标提示
- **房间标签**：顶部标签支持拖拽排序，可指定某个标签作为启动后默认打开的页面；标签过多时自动换行，不会挤出屏幕
- **自定义名称**：详情页标题旁可改设备名，只存本地、不影响手机端；改过的设备带「自定义名称」标记，可一键恢复云端原名。无公开规格的设备（仅蓝牙类）同样支持
- **卡片外显值**：设备卡片副标题默认显示温度与湿度，可在详情页改成任意可读数值（如插座的功率），最多两项，也可以选择完全不显示
- **环境概览**：房间栏下方一行状态胶囊，显示当前范围的温度、湿度、开启设备数与耗材不足数量，点击查看明细（设备卡片可直接开关）
- **场景执行**：主页「场景」选项卡列出米家 APP 中创建的手动场景，一键执行（可在设置中隐藏该入口）
- **定时开关**：给指定设备配「每天某时刻打开/关闭」，同一设备可配多条（如 7:00 开灯、23:00 关灯）；到点自动执行并提示，错过时间不补执行只提醒。**需应用保持运行**（最小化到托盘也算），关掉程序不会触发
- **设备控制**：根据设备 spec 元数据自动生成控件——布尔属性映射开关、数值属性映射滑块（自动套用范围与步长）、枚举属性映射下拉框
- **动作执行**：设备支持的动作渲染为按钮，执行前二次确认
- **系统托盘**：最小化到托盘，左键单击切换快捷控制窗口、双击直接唤出主窗口；支持快捷设备控制、场景一键执行、小爱音响快捷控制、小爱语音指令，快捷窗口支持单列/双列卡片切换与设备/场景混排排序
- **桌面挂件**：常驻桌面的设备控制面板——自选放哪些设备与场景、无级调透明度、单排最多放 9 张设备卡片、一键收起为细横条、背景色可调；窗口可置顶可锁定；开关在「设置 → 应用功能 → 桌面挂件」，开启后随应用启动自动显示；设备清单与托盘快捷窗口相互独立，卡片顺序可直接在面板上拖动调整
- **定时任务**：针对具体设备定时设置开启、关闭
- **虚拟开关支持**：针对多键开关虚拟的独立开关支持独立控制
- **主题配色**：深色 / 浅色 / 跟随系统；**控件主题色可自定义**（内置绿/粉/黄/蓝四档，也可打开取色板任选颜色，按钮、开关、选中态与浮窗统一跟随）
- **托盘图标配色**：默认跟随 Windows 任务栏深浅色自动切换，也可固定为黑、白、绿或任意自定义颜色
- **交互细节**：滚轮采用缓动动画（不再是逐条跳变）、工具提示按应用主题自绘（系统深色模式下不再黑底深字）、弹出面板统一淡入淡出
- **界面缩放**：50%–200% 无级调节（叠加在系统缩放之上），需重启生效
- **开机自启动**：可选，写入当前用户注册表（HKCU Run）
- **小爱语音**：主界面右下角悬浮按钮，输入文字指令发送给在线小爱音箱，可指定默认输出音箱
- **版本检测**：启动时自动检查 GitHub Releases 新版本，也可在关于页手动检测
- **本地缓存**：设置、托盘/工作台配置与设备缓存存放在用户数据目录（详见下方路径说明）
- **上游可升级**：mijiaAPI 仅作为 PyPI 依赖锁定在 `>=5,<6`，升级后跑 `python -m tests.smoke_test` 即可确认兼容性

## 无障碍支持（读屏软件）

支持 NVDA、争渡、讲述人、JAWS 等读屏软件。桥接层在 `app/ui/a11y.py` 中集中实现，只补充 Qt 的可访问名称、焦点策略与键盘入口，**不改变任何界面外观、布局和鼠标操作**，普通用户无需任何设置。

**可访问名称只补缺失的文字**：控件类型（按钮 / 复选框 / 选项卡 / 分组）、选中态与可用按键由读屏自己朗读，不重复写进名称；`accessibleDescription`（UIA 的 HelpText）恒为空，避免读屏在名称后追加一段帮助文案。只有读屏拿不到的信息（设备开关状态、在线状态、属性名、图标按钮用途、自绘滑块的当前数值）才写进名称。

控件在 Windows UIA 树中的名称示例（读屏会自行追加「分组」「复选框 未选中」等）：

```
储藏室灯，储藏室，在线，已关闭
储藏室灯，电源开关，已关闭
场景
```

键盘操作：

| 按键 | 作用 |
| --- | --- |
| `Tab` / `Shift+Tab` | 在顶栏、房间选项卡、设备卡片、数值滑块、按钮之间移动 |
| `Enter` | 打开设备详情 / 执行场景 |
| `Space` | 切换设备电源、切换设置开关、选择房间 |
| 方向键 | 数值滑块（设定温度、亮度、色温等）每次 ±1 |
| `Shift`+方向键 / `PageUp` / `PageDown` | 数值滑块大步长调整（量程大时自动放大） |
| `Home` / `End` | 数值滑块调到最小 / 最大 |
| `Ctrl+L` | 焦点跳回设备列表第一张卡片（网格刷新后尤其有用） |
| `Alt+1` … `Alt+9` | 直接切换到第 N 个房间 / 场景选项卡 |
| `F5` | 刷新设备 |
| `Alt+S` | 打开设置 |
| `Esc` | 关闭当前对话框 |

**每台设备在 Tab 链里只占一站**：设备卡片自身可聚焦（空格切电源、回车开详情），卡片内的圆形电源钮、详情页电源行的圆形按钮、场景卡片的运行按钮都不再单独接收键盘焦点，避免读到两个功能重复的焦点。这些按钮的可访问名称仍保留在 UIA 树里，鼠标点击行为完全不变；托盘快捷行与桌面挂件里的电源钮没有可聚焦的父卡片，仍是独立焦点。所有页面里那个只读「分组」的空焦点也已移出 Tab 链：Qt 默认给 `QScrollArea` `StrongFocus`，而它在 UIA 里没有名称，设备详情工作台、添加功能抽屉、主界面设备网格、调整标签顺序，以及设置 / 定时任务 / 托盘管理等页面的滚动容器都是同一个来源。现在 Tab 直接进入真正的控件，滚轮、滚动条、鼠标拖拽与内部控件焦点不受影响；代价是「聚焦滚动容器后按方向键翻页」不再可用，需要滚动时仍可用滚轮或滚动条。有可读名称的滚动容器不受影响。

「管理托盘项目」里原本只有 `+` / `✓` 的勾选按钮，现在名称是同一行的设备名 / 场景名（例如「Xiaomi 中枢网关 · 客厅」），读屏读成「Xiaomi 中枢网关 · 客厅 复选框 未选中」，而不是只念「+ 复选框 未选中」；同对话框的搜索框与房间筛选下拉也补上了可访问名称。勾选状态由读屏朗读，不再写进名称或帮助文案。

**托盘快捷控制的开关能分得清是哪台设备了**：托盘行只保存设备 ID，设备名与房间名画在同行标签上（还会按宽度省略），桥接层沿父链取不到设备对象，于是每个圆形开关都只念「电源开关，已关闭 按钮」。现在按设备 ID 反查窗口里的设备列表补上文字，读成「储藏室灯，储藏室，电源开关，已关闭 按钮」「客厅灯，客厅，电源开关，已开启 按钮」；开关翻转时状态同步更新，设备名与房间不会丢。场景行的执行按钮同理补上「场景名，家庭」。开 / 关状态仍留在名称里——这类圆形按钮不是复选框，读屏拿不到只用颜色表达的状态。显示文字、布局、鼠标点击与既有信号都不变。

**托盘快捷窗口的设备行：空格切电源、回车打开设备详情**：主界面的设备卡片本来就是这两个键，但托盘行没有可聚焦的父卡片，焦点落在行内唯一的圆形开关上，回车此前被「等价转发到 click()」的那条规则又切了一次电源，读屏用户没有任何键盘入口能打开设备详情。现在设备行的回车转发到窗口既有的 `open_device_requested(did)` 信号——鼠标左键点击行本体走的正是它（收起面板、打开详情对话框），副作用完全一致；空格仍由按钮原生的 `clicked` 切电源。场景行的回车仍是「执行场景」，小爱音频栏的切歌 / 播放、标题栏按钮、主界面卡片与其它窗口一概不受影响。长按回车的自动重复会被过滤，不会连弹出多个详情框。名称、显示文字、焦点策略、忙碌守卫与鼠标路径都没改：名称仍是「储藏室灯，储藏室，电源开关，已关闭」，不额外写「按回车打开详情」这类操作提示。

**托盘快捷控制的 Tab 焦点不再抖动**：主窗口每 3 秒轮询一次设备，面板可见时会整窗重建列表，把正持有键盘焦点的开关一起销毁；开关按下后业务层的忙碌禁用又会让 Qt 顺势把焦点挪到下一台设备。表现就是空格 / 回车时灵时不灵、Tab / Shift+Tab 反复落在同一个控件上。现在给窗口的重建套了一层内容指纹守卫：设备、开关状态、顺序、场景、列数与窗口宽度都没变时跳过这次重建（与桌面挂件「就地更新、不整窗重建」的既有做法一致），已从网格摘除、等待延迟删除的旧行整行退出 Tab 链；真需要重建时，按设备 ID / 场景 ID 把焦点放回同一台设备的新按钮。

**按空格 / 回车后不再先念下一项**：忙碌禁用还有第二层影响——Qt 在 `setEnabled(False)` 里是「先把焦点同步推给下一颗按钮、再发 EnabledChange」，读屏因此先念「空调，大厅，电源开关……」，往往读不全就又跳回原来的按钮。事后把焦点抢回来只会多一次播报，所以桥接层改为让这次禁用不发生：仅当托盘行按钮正持有键盘焦点、且禁用来自执行中的忙碌态时，保持按钮启用。忙碌配色与图标由业务的状态位和样式表决定，与 enabled 无关，视觉零变化；防连点改由桥接层在这期间吞掉鼠标点击与空格 / 回车，等价于原来的禁用。实测整个过程零次焦点事件，场景执行钮同理。设备状态、温湿度读数与在线状态照常刷新，鼠标焦点、鼠标点击和普通用户的界面外观完全不变；其它窗口的电源按钮仍按业务原样禁用。

「调整标签顺序」里每行都有一个文字相同的「设为默认」按钮，房间名只写在同行标签上，读屏逐行 Tab 时全部念成「设为默认 按钮」。现在名称补上所属房间，读成「客厅，设为默认」「卧室，设为默认」；某行被设为默认后，按钮变成禁用的「默认」标记，名称同步变成「卧室，默认」。按钮显示文字、点击信号与禁用行为都不变。

**按钮末尾不再多念「回车」**：Qt 会把对话框里获得焦点的 `autoDefault` 按钮报成 `Enter` 键盘快捷键，NVDA 于是在每个按钮名称后追加一声「回车」。桥接层关闭了 `QPushButton` 的 `autoDefault` / `default`，并把「回车激活焦点按钮」等价转发到原有的 `click()`，于是读成「Xiaomi 中枢网关 · 客厅 复选框 未选中」「外显值设置 按钮 设置设备卡片副标题显示的值」。鼠标、空格、回车三条操作路径的副作用与改造前完全一致；按钮自带的 tooltip 说明未作改动。

**下拉框末尾不再多念「下方向」**：Qt 把 `QComboBox` 无障碍接口的 `Accelerator` 固定报成 `Down`，UIA 于是填进 `LegacyIAccessible.KeyboardShortcut`，NVDA 在每个下拉框名称后追加一声「下方向」。它和按钮的「回车」同属用户不需要的按键提示。桥接层通过 `QAccessible.installFactory` 为所有下拉框返回一个代理接口，只把这一项报成空；名称、当前值、描述、子节点、角色、状态以及展开 / 取值 / 选择等 UIA Pattern 全部委托给 Qt 原生接口，方向键改值、`Alt+Down` 展开、可输入下拉框的筛选输入、鼠标点击与视觉外观都不变。定时任务里的「设备 / 小时 / 分钟 / 动作」以及其它窗口的房间筛选等下拉框一并生效；整个窗口里只剩 Windows 系统菜单自带的「Alt+空间」，那不是本程序的提示。

**定时任务里不再追加朗读悬停说明**：Qt 的 UIA 在 `accessibleDescription` 为空时会回退用 `toolTip` 填充 `FullDescription`，读屏于是把悬停说明在名称后追加念一遍——搜索框的「输入任意片段筛设备，回车从候选里选」带操作提示，开关的「停用后保留规则但不执行」是帮助文案，删除按钮的 tooltip 又与名称完全重复，会连念两遍。现在只在该窗口内用一个空白描述占位挡住回退：`toolTip()` 一个字不改（鼠标悬停提示照旧），UIA HelpText 仍为空；同时给四个原本无名的下拉框补上缺失的用途名「设备 / 小时 / 分钟 / 动作」，避免去掉拖尾后反而读不出是什么。其它窗口的 tooltip 说明保持原样。

**符号按钮不再只念一个「+」**：「添加设备功能」抽屉里每项原先只有一个 `+` / `✓` 按钮，整页 Tab 下来全是「+ 按钮」，既分不清是哪一项、也不知道按下去是添加还是移除。现在按钮名称带上所属功能的标题与当前动作，读成「添加 电源开关 按钮」「移除 亮度 按钮」；添加 / 移除状态翻转时名称同步更新，而按钮显示文字、既有信号与鼠标操作全部不变。同批修复还包括：详情工作台卡片上的 `↑` / `↓` / `✕` 改用既有 tooltip（「上移」「下移」「移除」）、「+ 添加功能」入口按钮去掉装饰符号、以及「管理桌面挂件」里同类 `+` / `✓` 勾选钮补上同行设备名。

**数值滑块可以用键盘调整了**：设备详情里的设定温度、亮度、色温等是自绘滑块，Qt 默认不接收键盘焦点，Tab 会直接跳过整张卡片；即便按键送到滑块，也只更新卡片上的预览数字，真正把值下发到设备的是「鼠标松手」那一步。现在这些滑块可 Tab 聚焦，方向键每次 ±1，`Shift`+方向键 / `PageUp` / `PageDown` 大步长（色温这类大量程会自动放大步长），`Home` / `End` 直达最小 / 最大；停止按键约 0.4 秒后按原有「松手才提交」逻辑统一下发一次，连按方向键不会连发几十条指令。Qt 的 UIA 不为这个自绘滑块提供数值，所以当前值补进了可访问名称，读屏会念「设定温度，26 滑块」并在调整后重读一次。组合卡片里的子滑块同样生效，滚动条不受影响；鼠标拖动、松手提交、外观与既有信号全部不变。

**设备详情的模式按钮能读出选中态了**：空调「运行模式」里的风扇、制冷、制热、除湿在界面上只靠背景色区分，按钮本身不是复选框，UIA 里四个都只是普通按钮，读屏 Tab 过去听不出当前选的是哪一种。现在桥接层让这组按钮具备原生选中态，并随设备回读、点击切换同步，读成「风扇 复选框 已选中」「制冷 复选框 未选中」；名称仍只有模式名，不写状态词。显示文字、配色、鼠标点击、写入设备的时机与既有信号都不变。四个按钮也始终各自留在 Tab 链里：业务把按钮放在 `QButtonGroup` 里，Qt 一旦发现它们变成可选中，就按单选组处理、只让一个按钮停靠 Tab，切换选中项后还会清掉其余按钮的 TabFocus；桥接层在设置选中态之前先把按钮从组里摘出（组本身没接任何业务信号），于是 Tab 又能依次走完风扇、制冷、制热、除湿，切换模式后也不退化。

**托盘里的小爱控制也能用键盘了**：顶部那栏的「上一首 / 播放 / 下一首」和音量条在业务里都被显式设成不接收焦点，Tab 会整段跳过。现在四个控件都进了 Tab 链且顺序与界面一致：按钮用空格或回车激活，音量条用方向键每次 ±1、`Shift`+方向键 / `PageUp` / `PageDown` 大步长、`Home` / `End` 直达两端，停止按键约 0.4 秒后按原有「松手才提交」逻辑下发一次。中间那颗圆钮实际是播放 / 暂停（静音）切换，名称随状态在「暂停」「播放」之间同步，与图标和悬停提示一致。音量条是原生 `QSlider`，Qt 的 UIA 会提供 RangeValue，读屏自己朗读当前音量，所以名称只写「音量」、不再把数值抄一遍；三个图标按钮的 tooltip 与名称完全相同，也顺手挡住了 Qt 把它回退成 `FullDescription` 后再念一次的重复。切歌 / 静音 / 提交音量时业务同样会短暂禁用控件防连点，这里沿用上面「不让禁用抢焦点」的做法，但只对键盘发起、且控件正持有焦点的那一次生效：鼠标点击仍按业务原样变暗，明眼用户看到的反馈一模一样。实测按键到请求返回整个过程零次焦点事件，鼠标拖动、预览刷新与既有信号都不变。

开关状态、Toast 通知与登录进度会通过隐藏的播报区域同步朗读。扫码登录仍需用米家 APP 扫描屏幕上的二维码（读屏用户可能需要他人协助或凭经验对准）。

回归测试：`.venv\Scripts\python.exe -m tests.a11y_test`（离屏运行，不需要米家账号）。

> 已知范围：主窗口核心链路（登录、房间切换、设备卡片、详情工作台含模式选中态、设置、状态胶囊）、托盘项目管理，以及托盘快捷窗口的按钮名称、键盘操作（设备行空格切电源 / 回车打开详情）、Tab 焦点与小爱音频栏已覆盖；桌面挂件、语音悬浮球的完整键盘导航留待后续迭代。

## 运行

要求 Python >= 3.10

> **无障碍增强没有独立开关、也没有独立程序**：它就是主程序本身，按下面的方式正常启动即自动生效，界面外观与鼠标操作完全不变。
> 从旧的 `MiHome-Windows.exe` 切换时，请先在托盘图标上退出旧版：两版共用同一个单实例锁，旧版仍在运行时启动新版只会把旧窗口带到前台，看起来像"没变化"。
> 源码模式默认把配置写在仓库根目录；若要沿用旧版已登录的账号和设备缓存，启动前设置 `MIHOME_DATA_DIR=%LOCALAPPDATA%\MiHome-Windows`。

### 一键运行

```powershell
git clone https://github.com/huanyuejue/MiHome-Windows.git
cd MiHome-Windows

# 双击 start.bat，或命令行执行：
start.bat
```

`start.bat` 自动完成：创建 venv → 安装依赖 → 启动程序，无需手动配置环境。

### 手动运行

```powershell
git clone https://github.com/huanyuejue/MiHome-Windows.git
cd MiHome-Windows

python -m venv .venv
.venv\Scripts\pip install -e .
.venv\Scripts\python.exe run.py
```

首次启动会弹出扫码窗口；之后凭据长期复用，失效时再次扫码即可。

源码模式下运行日志会同时写入项目根的 `debug.log`（结构化）与 `app.log`
（控制台原始输出 + 崩溃堆栈），排查问题时两个都值得看。

### 米家账号登录凭据

路径：`~/.config/mijia-api/auth.json`

这是 mijiaAPI 的认证文件，扫码登录后长期复用。失效时程序会自动提示重新扫码。

> 路径中的 `~` 在 Windows 上为 `C:\Users\<用户名>`。

**卸载重装为什么不用重新扫码？** 因为凭据不在安装目录、也不在

## 构建可执行文件

项目使用 **[Nuitka](https://nuitka.net/)** 将 Python 源码编译打包为原生 Windows 可执行文件（standalone 模式：把 Python 解释器、全部依赖与资源文件整合进一个免安装目录，最终产出 `dist\MiHome-Windows.exe`）。Nuitka 是真编译器——把代码编译为 C 再编译为机器码，而非 PyInstaller 式的"打包字节码"，这也是需要 VS Build Tools 的原因。

### 前置条件

| 工具 | 版本 | 说明 |
|------|------|------|
| Python | >= 3.10 | 需加入系统 PATH，构建脚本会自动创建 venv |
| C 编译器 | **MSVC（VS Build Tools / VS Community）** | 必须与 **Windows SDK** 一起装，见下 |
| 项目路径 | **纯 ASCII** | 路径含中文会导致构建失败，见下 |

**① 装 MSVC + Windows SDK（必须两个都装）**

打开 **Visual Studio Installer** → 修改已装的 VS：

- 「工作负载」标签 → 勾 **使用 C++ 的桌面开发**（会连带 Windows SDK）；
- 或「单个组件」标签 → 搜 `Windows SDK` → 勾 **Windows 11 SDK (10.0.26100.0)**
  （有 10.0.22621.0 也可以）。

> 只装 MSVC 不装 SDK 时，`cl.exe` 存在、vcvars 也能"激活成功"，但编译阶段
> 必然失败。构建脚本会**提前检查 SDK 并明确报错**。

**② 项目路径必须是纯英文**

Nuitka 依赖的 `depends.exe` 不支持非 ASCII 路径（会把中文写成 `0x04` 占位
字节），构建会在依赖扫描阶段崩掉。项目目录请放在纯英文路径下，
例如 `E:\Projects\MiHome-Windows`。构建脚本会先检查路径并提示。

### 一键构建

```powershell
cd MiHome-Windows

.\build.ps1
```

脚本自动完成：创建 venv → 安装依赖（含 Nuitka 本体）→ 激活 MSVC 环境 → Nuitka 编译
→ 输出到 `dist\MiHome-Windows.exe`，并做一次**隐私自检**（确认产物里没有
登录凭据与设备数据）。

> **产物不带个人米家信息**：账号凭据、设备列表、挂件/定时配置都只存在用户目录
> （见上节），编译时不会打进 `dist\`；隐私自检发现任何一份就报错终止。
> 别人拿到你的 `dist\` 或安装包，仍然是他自己的账号、自己的设备。

> **产物是"一个 exe + 一堆依赖目录"**，不是单文件。只拷 `MiHome-Windows.exe`
> 到别的机器是跑不起来的，必须整个 `dist\` 目录一起分发（或做安装包，见下）。

构建参数（打包资源清单、图标、排除项等）集中维护在 `build.ps1` 的 `$NuitkaArgs`；
`build_msvc.bat` 只是转发到它的双击入口。

首次构建耗时较长（创建 venv + 下载依赖 + Nuitka 编译，通常 5–15 分钟，视机器而定）

## 排查问题

出问题时先看日志：

- `debug.log`：结构化日志（源码模式在项目根，构建版在 `%LOCALAPPDATA%\MiHome-Windows\`），
  记录应用内捕获到的异常、后台任务失败与云端错误码。
- `app.log`：**仅源码模式**，把控制台原始输出与崩溃堆栈一并写入。程序崩溃时控制台窗口
  会随进程一起消失，事后只能靠这个文件——它同时接管了 Qt 的 C++ 层警告与段错误堆栈，
  每次启动会写一条 `===== 时间 启动 =====` 分隔线，方便区分是第几次运行。

云端返回的原始错误码可用诊断脚本查看：

```powershell
.venv\Scripts\python.exe -X utf8 -m tools.diag_switch
```

常见提示说明：

- 设备名显示为英文：多出现在国际版设备，程序会依次尝试规格里的中文名、产品页商品名；
  都不存在时保持云端原名，可用详情页的自定义名称覆盖。
- 详情页提示「该设备无公开的功能规格」：仅蓝牙类产品在云端没有下发规格，无法提供
  控制面板。这类设备仍可正常显示与改名，不影响其它功能。
- `开关状态读取失败 ... code=-704002000`：规格声明了开关属性但设备实际不支持，
  属于常态，这类记录按调试级别输出，不会出现在 `debug.log` 里。
